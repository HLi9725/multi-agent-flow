# 第四阶段客户端接入记录

本文记录 2026-10-13 在本机做过的 4D 客户端尝试。第四阶段没有全部通过。第 1 到第 4 节是双帧改动之前的记录，当时 4E 还未做。第 5 节是双帧落地后的再探测。D1–D8 没有一项改为已验证。

登记、令牌和临时配置只放在系统临时目录。本文不记录签名密钥、Bearer 或 `jti`。探测结束后已从本机 Claude 配置移除临时服务器名称；仓库没有新增 `.cursor/mcp.json`。

## 2. 已实测

下列命令是当天实际执行的。自动化测试只证明旧入口不依赖 `mcp` 包，不把 D1–D8 改成已验证。

```powershell
python -c "import mcp"
```

退出码 1。`ModuleNotFoundError: No module named 'mcp'`。没有安装该包。`python -m mcp --help` 同样因找不到模块退出码 1。

```powershell
claude --version
claude auth status
```

Claude Code 版本 `2.1.90`，`--version` 退出码 0。`claude auth status` 退出码 1，输出为 `loggedIn: false`。因此没有用模型会话去调用工具，也没有使用跳过权限的开关。

本机没有项目级或用户级 `mcp.json`。`cursor --add-mcp` 会把服务器写进会被自动加载的配置，本次没有执行。

STDIO 探测使用临时目录里的登记和包装命令，范围是 Claude 的 local 配置，工作目录是临时目录：

```powershell
claude mcp add --scope local --transport stdio yyflow-4d-probe -- <临时包装命令>
claude mcp list
claude mcp get yyflow-4d-probe
claude mcp remove yyflow-4d-probe -s local
```

`add` 退出码 0。`list` 退出码 0，健康检查约 68 秒后状态为 Failed to connect。`get` 退出码 0，约 36 秒后同样是 Failed to connect。随后在临时进程里抄到客户端首包 305 字节：以换行结尾的 JSON，方法是 `initialize`，`protocolVersion` 为 `2025-11-25`，`clientInfo.name` 为 `claude-code`，版本 `2.1.90`。首包没有 `Content-Length`。服务端标准错误为空。当前服务端 STDIO 仍是 4A 的 Content-Length 帧，这次没有改帧。

HTTP 探测把 compat 服务绑在 `127.0.0.1:18765`，标准错误出现 `MCP_HTTP_LISTENING 127.0.0.1 18765`。签发命令退出码 0，令牌没有写入仓库。直连该地址时，Claude 的 HTTP 健康检查退出码 0，状态文本为 Connected。

为了看请求形状，又经 `127.0.0.1:18766` 做了一次只转发、不记录令牌的观察。Claude 仍打印 Connected，但进程随后出现 libuv 断言，退出码 `3221226505`。转发记录只有两条：

| 请求 | 结果 |
| --- | --- |
| `POST /mcp`，方法 `initialize`，Accept 同时包含 `application/json` 和 `text/event-stream`，带 Authorization，无会话头 | HTTP 200，`application/json`，响应带会话头 |
| `POST /mcp`，方法 `notifications/initialized`，带会话头，`MCP-Protocol-Version: 2025-11-25` | HTTP 202 |

没有 `tools/list`，没有 `tools/call`，没有 GET，也没有看到 SSE 事件。探测进程结束后端口已关掉，Claude 配置里的临时服务器名称和令牌已不在。

旧入口回归：

```powershell
python -m pytest -q tests/test_legacy_entry_without_mcp.py tests/test_workflow_profile.py --tb=short
```

17 passed，1.82 秒，退出码 0。其中两条新测试断言导入不要求 `mcp`，并且在未设置 MCP 环境变量时 `tests/test_workflow_profile.py` 可以被收集。这不证明 D8 的子代理全链。

开工时的领域 CLI 领取发生在未安装 `mcp`、未配置 MCP 的前提下，退出码 0。该命令只说明这条 CLI 当时可执行，不把 D8 标成已验证。

## 7. 2026-10-14 Cursor 真实客户端

客户端是 Cursor 3.24.12。传输是本机 STDIO。隔离项目是临时目录中的 `alpha`，不是仓库看板。配置曾写在 `C:\Users\user\.cursor\mcp.json`，测试结束后已删除。登记和看板仍留在 `C:\Users\user\AppData\Local\Temp\yyflow-4d-cursor-d2zft3kd\`。响应中没有令牌或连接串。

第一次连接只授予 `read`，工具列表是 `get_project`、`get_task`、`list_tasks`、`get_status`。`create_task` 被客户端拒绝，没有发出写入。随后只给主体 `principal-dev` 的项目 `alpha` 增加了 `task.transition`。旧服务器名称的界面仍显示最初的 4 个工具。换成新名称后，真实客户端列出 `create_task` 和 `transition_task`。没有调用 `transition_task`。

| 时间 | 工具 | 参数摘要 | 结果 |
| --- | --- | --- | --- |
| 09:28 | `get_project` | `project_id=alpha` | 返回 `alpha` / `org-1` / `offline` |
| 09:28 | `list_tasks` | `project_id=alpha` | 空列表 |
| 09:28 | `get_task` | `task_id=T0001` | `NOT_FOUND` |
| 09:28 | `get_project` | `project_id=missing-project` | `UNKNOWN_PROJECT` |
