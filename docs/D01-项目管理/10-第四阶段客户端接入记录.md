## 8. 人类验收通道

2026-10-14 起，MCP 工具 `request_acceptance` 只负责申请验收。它不能把任务改成「已验收」。环境变量 `YY_FLOW_MCP_ACCEPTANCE_CONFIRMED` 不再授予验收。STDIO 和 HTTP 都把上下文里的 `acceptance_confirmed` 固定为假，并忽略该环境变量。模型参数里的同名开关会在进入工具前被丢弃。历史证据文件保留，不因这次改动删除。

申请成功时，服务端用不可预测编号写入项目数据根 `mcp_auth/acceptance/<编号>.json`。返回里有项目、任务、检查点上的最新候选 SHA、验收契约哈希、质量证据摘要、拟执行动作 `accept`、编号和过期时间。任务状态保持「已完成」。同一幂等键再次申请返回同一编号。默认有效期 15 分钟。契约绑定验收条目和最新候选。质量摘要来自独立审查与测试，或 Lite 的 Verifier，不来自用户确认本身。批准前仍要走现有 EvidenceGate。没有检查点或质量链时，申请会被拒绝。

真实用户演练尚未执行。下面的步骤只说明本地通道怎么用，不能把 D7 或第四阶段改成已通过。没有新增界面，也没有改 Cursor 的 MCP 配置。Production Runner 的 `accept` / `reject` 仍是另一条入口，语义不变。

## 9. 申请、批准、拒绝和恢复

申请由已登录的 MCP 客户端调用 `request_acceptance`，并带上项目、任务、当前版本、幂等键和证据编号。调用结束后用 `get_task` 确认状态仍是「已完成」，并记下返回的确认编号、候选 SHA、契约哈希和过期时间。

批准只在本机交互式控制台执行。命令会要求在控制台设备上重新输入确认编号；管道标准输入不能批准。身份来自操作系统进程令牌，不来自环境变量，必须与登记里的 `local_principals.os_user` 一致，且对该项目有 `acceptance` 范围。同一操作系统账户不能单独证明是人在操作。不要传用户编号冒充别人；即使命令行带了用户编号，服务也会忽略。

```powershell
python scripts/mcp_server.py acceptance --registry <登记文件> --id <确认编号> --decision approve
```

拒绝使用同一命令，把 `--decision` 换成 `reject`。拒绝会把原任务从「已完成」退回「已退回」，不新建任务。

```powershell
python scripts/mcp_server.py acceptance --registry <登记文件> --id <确认编号> --decision reject
```

编号错误、过期、候选 SHA 变化、契约变化、跨项目、跨任务或跨主体都会拒绝。门禁失败不会把任务改成「已验收」，也不会把这次申请记成已消费的成功验收。批准和拒绝同时发生时，以先写入磁盘的决定为准。成功验收后记录已消费；看板已经是「已验收」且记录已消费时，再次批准只返回原结果。

进程中断后，按磁盘上的 `mcp_auth/acceptance/<编号>.json` 恢复查询。文件里有项目、任务、候选、契约、决定和是否已消费。不需要靠进程内存。业务状态已经推进、但终态审计没有写成 OK 时，再次执行只补记审计，不重复流转，并返回「业务已应用、审计待补记」。开始审计都没有写成功时，看板保持原状态。

本次没有对真实任务执行上述批准或拒绝。第四阶段没有全部通过。

## 10. 验收质量门禁与中断恢复复修

2026-10-14 沿用 T0040 修复复验发现的问题，不替代第 7 节的真实 STDIO、HTTP 记录，也不冒充真实用户确认演练。

- 引用质量证据逐份走共享 EvidenceGate：产物必须存在且哈希匹配；QA 开启完整语义检查。MCP 产物路径相对登记授权的 `data_root`，不从模型参数或检查点猜测更广的父目录；现有 Runner 的项目根路径证据需按登记范围对齐。
- 验收覆盖与权威 AC 集合精确一致，无未知、重复、缺项或 FAIL。审查中的显式 REJECT 不允许被流转目标覆盖，QA 的负向场景和报告测试退出码也必须通过。检查点存在时，只使用登记任务检查点列出的证据，核对候选、基线、主契约、角色会话和调用；过时或不完整证据应重新生成，不能为兼容直接放行。
- Lite 证据持久化完整 Verifier 报告、验收哈希和 Runner 检查引用，MCP 复核时复用相同协议解析器。没有报告的历史证据不能冒充完整验证。
- 决策执行前保存版本及恢复契约；状态流转携带该编号的唯一决策标记。业务已经落盘而消费记录失败时返回 `APPLIED_LEDGER_PENDING`，审计失败返回 `APPLIED_AUDIT_PENDING`。重启核对该次决策后只补齐记录/审计，不再流转；已经应用的决策可以在编号过期后完成补记，未应用的过期批准仍拒绝。
- CLI 在读取控制台确认前展示项目、任务、候选 SHA、契约哈希、动作和期限。同账号可开伪终端的模型仍不能被本通道识别为非人类；此限制保留，须由宿主授权隔离保障。

反例测试包括缺失/篡改产物、错误验收哈希、未知/缺失/重复/失败覆盖、REJECT 冲突、失败命令和负向场景、Lite 报告与检查不一致、批准/拒绝落盘后消费记录失败的第二 Python 进程恢复。以上自动化隔离数据均为测试双重，不计为真实用户批准或拒绝。
