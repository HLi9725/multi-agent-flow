# 第四阶段远程部署与认证说明

本文只记录 4C 已经落地的本机试验边界。第四阶段没有全部通过。4D 客户端和 4E 连接器未做。本文不作为生产上线说明。

## 1. 本批不进生产

HTTP 进程只绑定回环地址，拒绝 `0.0.0.0`、空主机和非回环地址。进程内不做 TLS 终止。若以后放到非本机，TLS 由外部反向代理承担，本批不部署该代理，也不打开公网监听。

默认传输是 `--transport-backend compat`。不把 PyPI 包 `mcp` 写成全仓强制依赖。未安装 SDK 时，STDIO 和 compat HTTP 仍可使用。

## 2. 数据目录

登记文件由本机管理员写入，例如某个数据目录下的 `mcp_registry.json`。与它同级的目录：

| 路径 | 内容 | 谁可以写 |
| --- | --- | --- |
| `mcp_registry.json` | 项目登记、`token_audience`、签名密钥 `token_secret` | 本机管理员。模型与 MCP 工具不能改 |
| `mcp_auth/grants.json` | 授权表。主体、组织、角色、按项目的 scope | 由登记播种；管理命令不把模型字段写入这里 |
| `mcp_auth/revocations.jsonl` | `jti` 撤销。只追加 `revoked_at`，不物理删行 | `mcp_server.py auth revoke` |
| `mcp_auth/rate_buckets.json` | `(principal_id, project_id)` 令牌桶余量 | HTTP 进程。重启不把当前窗口清零 |
| `mcp_audit/` | 审计链 `events.jsonl` 与 `chain.tip` | 服务追加。缺行或摘要断裂时写工具 Fail-Closed |
| `<data_root>/mcp_idempotency/` | 按项目的幂等账本 | 写工具在领域写入前先记 pending |
| 看板与 Evidence | 仍在登记的 `data_root` 内 | 只经现有领域函数。HTTP 不接受原始文件字节 |

签名密钥只放在登记文件。响应、错误和审计不回密钥，也不回 Bearer 令牌。

HTTP 进程只打开登记文件和登记里已经解析好的数据根。工具参数里的路径、命令和 `user_id` / `tenant_id` 不作为授权，也不当成要读取的磁盘位置。

## 3. 保留策略

本批没有自动删除任务。建议由持有签发权的本机管理员保管：

- 撤销列表永久保留，直到在副本上做归档。禁止为了“清理”删掉 `revoked_at` 行。
- 审计与幂等账本至少保留 180 天，便于超时和重启后的对账。
- 备份目录至少保留 30 天，并且不要放进仓库或生产数据目录。
- 演练恢复只能写到新的副本目录。命令会拒绝与现用数据目录重叠的目标。

恢复顺序固定：登记与撤销列表，然后幂等账本，然后看板与 Evidence。恢复结束时抽查一条已完成幂等键，确认任务仍在副本看板中。

## 4. 谁持有签发权

只有能读取登记文件中 `token_secret` 的本机管理员可以签发或撤销。命令是本地管理子命令，不是 MCP 工具：

```powershell
python scripts/mcp_server.py auth issue --registry <登记文件> --principal-id <主体> --scope read --ttl-seconds 3600
python scripts/mcp_server.py auth revoke --registry <登记文件> --jti <jti> --principal-id <主体>
python scripts/mcp_server.py auth backup --registry <登记文件> --dest <空目录>
python scripts/mcp_server.py auth restore --src <备份目录> --dest <新副本目录>
```

令牌使用标准库 HMAC（`header.payload.sig` 的 base64url）。scope 是授权表与令牌 scope 的交集，不会自动带上更低级 scope。有效期在时钟偏移 60 秒内校验。失败对外是 `UNAUTHENTICATED`；已撤销或主体停用是 `REVOKED`。细节只进审计。

监听：

```powershell
python scripts/mcp_server.py http --registry <登记文件> --host 127.0.0.1 --port 8765
```

`--host` 省略时也是 `127.0.0.1`。

## 5. 协议与 SDK

2026-10-13 对照 `https://modelcontextprotocol.io/specification/2025-11-25/basic/transports`：

- 协议版本字符串保持 `2025-11-25`。
- 单一端点 `POST /mcp` 与 `GET /mcp`。
- POST 的 Accept 必须同时包含 `application/json` 和 `text/event-stream`。本批工具结果用 JSON 单对象。
- 会话头常量是 `MCP-Session-Id`。initialize 响应带上该头；之后缺头返回 HTTP 400。
- 后续请求必须带 `MCP-Protocol-Version: 2025-11-25`，不符返回 HTTP 400。
- 会话建立后的 GET 返回短 SSE 心跳并结束。

PyPI 包名仍是 `mcp`，核对时的发行版本为 2.3.0（Python >=3.10）。当前解释器执行 `import mcp` 失败，异常为 `ModuleNotFoundError`。没有为了通过而安装到用户环境。`--transport-backend sdk` 因此未启用。

## 6. 已实现

- compat Streamable HTTP、回环绑定、Bearer、受众、有效期、签名、撤销、停用、scope 交集。
- 读每分钟 60 次、写每分钟 20 次，计数落在 `mcp_auth/rate_buckets.json`。
- 单工具超时默认 15 秒；测试可注入更短超时。超时后幂等账本保持 pending，不另起一次无账本写入。
- 审计链断裂时写工具返回 `GATE_REJECTED`，`details.reason=AUDIT_GAP`；读工具继续。
- 备份，以及只在副本上的恢复和幂等抽查。

## 7. 已实测

下面两条是 2026-10-13 在当前工作区实际跑过的命令。自动化测试不能代替后面的独立进程演练。

```powershell
python -c "import mcp"
```

退出码 1。`ModuleNotFoundError: No module named 'mcp'`。没有执行 pip 安装。

```powershell
python scripts/mcp_server.py http --transport-backend sdk
```

退出码 2。标准错误只有“官方 SDK 后端未启用”。

```powershell
python -m pytest -q tests/test_mcp_stdio.py tests/test_mcp_write.py tests/test_mcp_http_auth.py --tb=line
```

26 passed，退出码 0。这只覆盖上述三个文件。

独立进程演练使用临时数据目录，不读取仓库里的 `user_data/board.json`。步骤与结果：

1. `python scripts/mcp_server.py auth issue --registry <临时登记> --principal-id principal-dev --scope read --scope task.transition --ttl-seconds 600`，退出码 0。标准输出不含签名密钥。
2. `python scripts/mcp_server.py http --registry <同一登记> --host 127.0.0.1 --port 0`。进程打印 `MCP_HTTP_LISTENING 127.0.0.1 <端口>` 后开始服务。
3. `POST /mcp` initialize，HTTP 200，响应带 `MCP-Session-Id`。
4. `notifications/initialized`，HTTP 202。
5. 带 Bearer 调用 `create_task`，HTTP 200，`isError=false`，任务 `T0001`。
6. 带同一令牌调用 `get_task`，HTTP 200，状态为待开始。
7. 杀掉该进程。`wait` 得到的进程退出码是 1，这是终止后的子进程码，不是签发或调用失败。
8. 用同一登记再次启动 `http --host 127.0.0.1 --port 0`，重新 initialize，HTTP 200。
9. 用同一幂等键再次 `create_task`，HTTP 200，`replayed=true`，任务仍是 `T0001`。
10. `list_tasks` HTTP 200，只返回 `T0001`。
11. 再次杀掉进程，`wait` 退出码 1。演练驱动进程退出码 0。

响应正文没有出现签名密钥或 Bearer 令牌。这次演练不证明 SDK、真实客户端或生产部署可用。
