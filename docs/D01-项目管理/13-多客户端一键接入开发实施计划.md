# 多客户端一键接入与共享安装补强实施计划

## 1. 目标与基线

用户要求：下载 YY-Flow 后执行一次明确授权的接入命令，自动准备项目角色、规则和 Cursor、Codex、Antigravity 的 MCP 连接，不再逐个手填绝对路径。支持项目内安装，也支持一份中立工具代码供多个项目使用，各项目数据和权限独立。

基线：`df69d7582e8eb3477ae69b9f8de4fa3e3a21636a`。仅在 `feature/S4-mcp-integration` 开发，不在 main 编码。第四阶段既有验收结论及终态任务保持不变；本批属于后续接入补强，不重做 MCP 核心，也不将后续兼容项补记为已通过。

本计划是待实现契约，不是已实现功能说明。下述新增命令及参数在开发并测试前不可作为现成入口执行。

## 2. 已有实现与缺口

- `verify_and_export_agents.py` 已能导出角色和规则；当前按既存宿主目录探测，空项目不能仅因此省略用户明确选择的客户端。
- `paths.py` 已区分工具代码和项目数据；共享标记否决 legacy 数据识别，MCP 有请求级数据根隔离。
- `mcp_server.py stdio --registry ...` 已提供服务；统一生成三客户端配置及项目登记的接入入口缺失。
- `install_global.ps1/.sh` 仍硬编码旧上游与不同 release 分支，使用覆盖式下载；更新前保护、退出码检查和源码版本核验不足。
- `init_skill.ps1/.sh` 是旧完整初始化，不是既有项目的无副作用接入入口；不能为了配置 MCP 重复建卡、归档文档或改写现有数据。

## 3. 范围与不做事项

本批交付：确定性接入 CLI、项目内配置合并、角色规则导出、共享安装安全补强、状态诊断、反例测试、隔离演练和使用文档。

不做：公网部署、HTTP/SSE 新兼容、SDK 新后端、自动提高写入权限、全局 Host 安全设置修改、Git hooks 自动执行、自动 push/merge/tag、业务项目迁移或数据库操作。不得新增“传入编号即真实宿主”的证据入口。

`git clone` 只下载代码，不能自动执行接入。项目可信确认、工具启用、操作系统授权等宿主交互不能绕过。默认只生成项目级配置，不改用户全局配置。

## 4. 接入接口与职责

建议新增薄入口 `scripts/setup_project.py`，实际逻辑放私有安装模块。参数至少覆盖：明确的 `--project-root`、`--skill-root`、`--clients`、`--python`、`--dry-run`、`--apply`、`--json` 及只读状态诊断。最终名称可调整，但必须在报告与文档中提供唯一入口及对应测试。

- 默认预览；`--apply` 才允许写入。用户显式选择全部三客户端时，目录尚不存在也要按规范生成；不能以未安装某宿主推断该配置已被真实客户端验证。
- 一次 apply 包括预检、配置规划、角色规则导出、项目登记、客户端配置和本地自检；失败返回非零，不得仅打印成功文案。
- 新项目需要的初始运行配置必须通过受测初始化逻辑创建；没有架构鉴定结论时标为未初始化，不伪造完成。重复执行不新增架构任务。
- 已有项目仅接入或更新受管配置，不重复跑完整初始化，不移动数据。提供缺失条件与明确修复建议，不擅自新建第二份空看板。
- 项目内安装直接复用 `.yy-flow/skill`。共享模式显式选择中立代码根，拒绝把某个业务项目的 `.yy-flow/skill` 当全局共享正本，以免默认数据根指向该项目。
- 共享模式各项目可保留轻量指向和生成配置，但不得再复制完整工具源码。无链接权限时报告可行动失败或使用明确记录的绝对脚本入口，不静默退化为整份复制或申请管理员权限。

## 5. 配置与安全契约

### 5.1 三客户端与项目登记

- Cursor：项目 `.cursor/mcp.json` 中的单个 YY-Flow 条目；导出 `.cursor/rules/` 和 `.cursor/agents/`。
- Codex：项目 `.codex/config.toml` 中独立的 `mcp_servers` 表；导出已支持的项目角色。必须保留现有注释、非受管表和其他 MCP 服务，不能整份重写用户 TOML。
- Antigravity：项目 `.agents/mcp_config.json` 中单个条目及既有角色导出。实现前查证当前官方配置规范；不凭旧路径猜测写全局配置。
- 服务端登记默认只授予指定项目 `read`；`task.transition`、`evidence.submit`、`acceptance`、`admin` 不自动增加。不得继承进程里的 GitHub Token 到生成文件。
- Python 路径应来自实际解释器探测或显式参数，并校验所需版本和依赖；不能硬编码开发者用户名、盘符或本机路径。参数列表执行，禁止拼 shell 字符串或使用 `shell=True`。
- 依据现有项目真实布局解析业务根、authority root、看板、锁、检查点和 Evidence 根。出现多个候选或超出安全边界的路径时停止并说明，不能用路径猜测、空看板或复制证据来凑齐。

### 5.2 合并、幂等和失败恢复

1. 记录受管条目、生成文件哈希、安装模式和代码版本；相同输入重复执行不重复添加、重写无关内容或扩大权限。
2. 同名非受管配置或用户修改过的生成文件视为冲突，给出有限差异并非零退出；不静默覆盖、重命名绕过或写入额外服务器。
3. 所有文件先解析和检查，再写入。坏 JSON/TOML、依赖缺失、路径逃逸、只读目录应在可判定范围内尽早失败。
4. 多文件写入要有计划、排他锁、原子替换和持久化进度；备份只覆盖本次受管文件，恢复不覆盖事务后用户新改动。中断后可诊断并恢复，不把部分成功宣称为整体完成。
5. 真实路径检查覆盖符号链接、Junction、父目录跳转和跨项目根。共享正本与其他项目不能因当前项目接入而写入运行数据。
6. 升级只更新工具代码及受管导出；保留看板历史、Checkpoint、Evidence 和预算。不使用 reset --hard、覆盖式 degit --force 或不受控递归删除。
7. 本地卸载只移除仍与受管哈希一致的自身条目；保留其他服务器、用户自改和全部业务运行数据，不删除整份客户端配置文件。

## 6. 共享安装补强

两平台安装器统一支持明确仓库源和分支/固定版本；本项目默认源为 `HLi9725/multi-agent-flow`，默认稳定入口 main，记录最终解析 SHA。不把本开发分支提前写成稳定默认。

下载到隔离暂存位置后验证，再应用到受管正本。更新前检查已有改动和运行数据污染；脏目录停止，不自动 stash。外部命令每步检查退出码，失败不写成功标记。`git pull origin <ref>` 不能被当作切换指定 ref 的通用实现。

保留可用的旧正本与恢复信息，避免更新过程中多个项目加载到半套文件。共享代码运行中的更新边界要明确：不能证明安全热更时拒绝更新或要求停用相关进程后再执行，不擅自结束用户进程。

## 7. 实施顺序

1. **A：预检与契约**。落定命令接口、安装模式、受管清单、错误码、路径映射及事务恢复方案，先写关键反例。
2. **B：项目接入**。实现三客户端配置安全合并、显式角色导出、只读登记、本地诊断与幂等行为。
3. **C：共享代码与更新**。补齐旧安装器安全保护，验证两个项目共用中立代码但数据独立，支持既有项目内安装继续使用。
4. **D：演练与交付**。独立 Reviewer、QA；冻结后一次最终全量。更新 README 与《YY-Flow单角色与完整自动编排使用指南》，区分已实现、协议自检、真实客户端现场证据。

保持同一个实施任务追踪缺陷与复验，不因退回新建修复卡。不得将 A–D 各自变成重复全量测试的机械门槛。

## 8. 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| AC-01 | 空白隔离项目执行一次 apply，生成所选三客户端配置、只读登记和必要角色规则；不依赖目录预先存在 |
| AC-02 | 同参数重复 apply，配置不重复、受管内容无实质变化，任务数及权限不增加 |
| AC-03 | 保留第三方 MCP、TOML 注释及非受管字段；同名冲突、坏配置和用户改动非零拒绝且不覆盖 |
| AC-04 | 中文、空格路径及非默认 Python 路径可用；命令参数不经 shell 求值，不包含任何本机固定用户名 |
| AC-05 | 两个项目使用同一中立代码根；项目A只操作A，项目B只操作B；共享正本不生成项目数据，含冷启动及并发反例 |
| AC-06 | 既有 `.yy-flow` 及受支持 legacy 布局看板、检查点和证据保持；布局歧义或越界拒绝，不能新建空看板掩盖 |
| AC-07 | 故障注入覆盖第二/第三配置文件写入失败及进程中断；恢复不重复、不扩大授权、不覆盖用户后续修改 |
| AC-08 | 工具/依赖缺失、网络失败、权限拒绝、符号链接逃逸和项目锁争用均返回明确非零结果；不得假成功 |
| AC-09 | 共享安装器来源及版本可指定，默认源一致；脏正本拒绝更新，失败保留旧可用版本，检查子进程退出码 |
| AC-10 | 未选择的客户端与用户全局设置不变；生成内容无凭据；只读凭据不能建卡、流转或验收 |
| AC-11 | 有界 STDIO 自检完成 initialize、tools/list、项目与任务读取、未知项目及写入拒绝；不改真实业务数据，不冒称真实客户端连接 |
| AC-12 | 受管移除只移除自身未被改动的条目，保留其他配置及运行数据；变更过的条目拒绝自动删除 |
| AC-13 | 最终反例、影响回归、全量 pytest、安全扫描及 diff 检查通过；主文档提供真实可执行的一条命令及适用边界 |
| AC-14 | 新增项目在真实 Cursor 中完成发现及只读查询；Codex/Antigravity 各自记录实际探活结果，未实测不写通过且不无界循环；未完成现场项交Codex决定是否接受范围，开发者不能自行结项 |

## 9. 测试与验收交接

复用 `tests/test_paths.py`、`test_export_global.py`、`test_init_skill_windows.py` 与 MCP 隔离回归，并新增安装接入专项测试。下载与失败用测试替身覆盖；仅经授权的真实连接用于现场证据。

Windows 至少覆盖当前 Python 及 Windows PowerShell 5.1 的解析与原生命令非零传播。Linux/macOS 没有实际环境时，不把静态 shell 检查写成真实安装成功。默认测试不访问 GitHub、不改用户 HOME、不使用正式客户端配置。

开发阶段先反例和影响回归。最终源码冻结后执行一次 `python -m pytest -q --tb=line`，再执行 `python scripts/check_secrets.py` 与 `git diff --check`。源码变化导致受影响证明失效时才补验证；不因角色切换反复全量。

所有演练优先用临时项目和假 HOME。`vehicle-audit`、`benchi` 等真实项目在开发期只读，首次真实迁移或改配置需列出目标及差异并另获用户授权。不得重用旧沙箱授权操作真实项目。

交付包含候选 SHA、真实角色调用记录、AC 对账、命令及退出码、恢复反例、实际变更文件和未验证边界。Cursor 可生成中文规范的本地候选提交，不 push、不合并、不打标签、不代验收；最终由 Codex 复验。
